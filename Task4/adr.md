### **Решение**
Для обеспечения доступа к актуальным ставкам по депозитам для кол-центров предлагается следующее решение:

1. **API для получения ставок**:
    - Расширить сервис управления ставками, добавив API для получения актуальных ставок по депозитам
    - Система кол-центра банка будет интегрирована с этим API для получения актуальных данных

2. **SFTP-решение для партнёрского кол-центра**:
    - Развернуть SFTP-сервер в инфраструктуре банка
    - Настроить автоматическую выгрузку файлов со ставками из сервиса управления ставками на SFTP-сервер
    - Обеспечить партнёрскому кол-центру защищенный доступ к SFTP-серверу для получения файлов

3. **Обновление систем кол-центров**:
    - Модифицировать интерфейс системы кол-центра банка для отображения актуальных ставок
    - Предоставить партнёрскому кол-центру спецификацию формата файла со ставками для корректной интеграции в их систему

**Диаграммы C4 представлены в отдельных файлах**.

**Логика принятия решений**:

1. **Выбор REST API для кол-центра банка**:
    - Система кол-центра банка имеет возможность интеграции через API
    - REST API обеспечивает наиболее оперативное получение актуальных данных
    - Использование существующей инфраструктуры банка без дополнительных компонентов

2. **Выбор SFTP для партнёрского кол-центра**:
    - Партнёрский кол-центр не имеет возможности интеграции через API-вызовы
    - SFTP обеспечивает безопасную передачу файлов
    - Возможность автоматизации процесса выгрузки и загрузки файлов

3. **Периодичность обновления данных**:
    - Для кол-центра банка - по запросу, актуальные данные в режиме реального времени
    - Для партнёрского кол-центра - периодическая выгрузка (например, каждые 10 минут или при изменении ставок)

### **Альтернативы**
1. **Email-рассылка файлов со ставками**:
    - Отправка файлов по электронной почте в партнёрский кол-центр
    - Отклонено из-за сложности автоматизации и меньшей безопасности

2. **Доступ партнёрского кол-центра к API банка через VPN**:
    - Предоставление защищенного доступа к API сервиса управления ставками
    - Отклонено из-за указанного ограничения, что партнёрский кол-центр не может использовать API-вызовы

3. **Общая база данных для ставок**:
    - Создание репликации базы данных со ставками для кол-центров
    - Отклонено из-за сложности реализации и потенциальных проблем с безопасностью

### **Недостатки, ограничения, риски**

1. **Задержка в обновлении данных для партнёрского кол-центра**:
    - Файловый обмен через SFTP создаёт задержку в обновлении данных
    - Партнёрский кол-центр может использовать неактуальные данные в период между обновлениями

2. **Зависимость от доступности SFTP-сервера**:
    - При недоступности SFTP-сервера партнёрский кол-центр не сможет получить актуальные данные
    - Необходимо предусмотреть резервные каналы связи или уведомления о сбоях

3. **Требования к безопасности**:
    - Передача данных о ставках должна осуществляться по защищенным каналам
    - Необходимо обеспечить строгую аутентификацию и авторизацию для доступа к данным

4. **Согласование формата данных**:
    - Требуется дополнительная работа по согласованию формата файлов со ставками
    - Необходимость поддержки совместимости при изменении структуры данных

5. **Ограниченная масштабируемость файлового решения**:
    - При значительном увеличении объема данных или частоты обновлений файловое решение может стать неэффективным
    - В долгосрочной перспективе может потребоваться пересмотр архитектуры интеграции с партнёрским кол-центром
